# XLLoop 组织与内部项目配置

本版支持三个开发组、共享运维、区域CEO授权和内部使用者反馈闭环。旧项目与成员不会自动获得新的区域审批额度。

## 初始化顺序
1. 工作台右上角设置 → 组织与项目分工：建立区域，给三个开发组命名。
2. 成员与权限：添加成员，并由成员使用受支持的身份登录完成绑定；可以暂不授予项目。
3. 项目归属与职责：选择内部/外部、所属区域、开发组，指定业务负责人、产品负责人、验收人及额外工程师。
4. 成员与权限：配置开发组职责、共享运维、区域CEO查看与审批额度，或者项目单独多职责。

## 权限原则
- 同一人可同时承担产品、全栈工程师、运维等职责，取权限并集。
- 组内产品/开发职责继承到该开发组负责的多个项目；共享运维继承到三个组所负责的项目。
- 区域CEO查看区域项目，预算审批、批准新立项分别显式开启；查看权不授予技术执行权。
- 每个区域分别设置单项目累计上限、区域累计承诺预算上限。所有已批准项目预算（包括集团批准的预算）纳入区域累计；续批排除本项目原额度后按新总额度计算。
- 项目单次执行额度与累计项目预算分别检查；默认零，无付费授权。
- 项目分工只能选择有效且已登录绑定的成员。停用、到期后下一次请求立即失效。
- 集团负责人保留全局权限，区域CEO不能自行增加额度或修改组织配置。

## 内部项目
使用者反馈 → 产品确认 → 全栈开发 → 大模型辅助测试与CI → 工程师复核 → 共享运维部署 → 指定使用者验收。

内部计划不包含推广任务，后台不会安排推广/SEO/GEO扫描；执行器接口再次阻止这些任务。历史推广记录保留但不能新增或修改。

发布/CDN/恢复前，必须存在执行器完成的测试证据，并有工程师对该报告指纹的复核。人工标记测试不能替代自动报告。测试报告改变会使旧复核和验收失效。使用者验收必须在有部署证据后进行。大模型测试只有在外部执行器、模型和CI实际接通后才会运行，本版不伪造测试结果。

## 预算和审批
员工或业务负责人可申请已有项目的累计预算。授权区域CEO在额度内审批，超额保持待审批，由集团负责人处理。区域CEO批准新立项还需要单独启用立项权。预算记录不代表已执行银行付款。

## 当前接入边界
- 不自动创建现实组织成员、CEO审批额度或云资源。
- david@xinlung.com 不是现有Site所有者登录的替代实现；独立邮箱登录需要部署时接入身份服务。
- 企业微信、模型、CI、IBM和阿里云的真实凭据与执行器需由技术人员接入；现有后台自动巡检保持原状态。
- 网站访问范围维持当前私有状态。应用内成员权限不自动改变网站外层访问名单。
